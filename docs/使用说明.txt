1. 这是什么
================================================================

一个单文件的网页程序，用来做整点时间记录：每个整点提醒你一次，
填写刚过去的那一小时做了什么，之后按日／周／月／年回顾时间分配。

核心设计目标是「警惕每一小时是否过得有意义」，所以除了记录内容和
类别之外，还可以给每小时打一个主观标记：有意义／一般／虚度。这是
唯一一项图表算不出来、只有你当时知道的信息，也是总结里最有价值的
一栏。

整个程序就是一个 HTML 文件，不依赖服务器、不需要账号、不加载任何
外部资源，完全离线运行。所有统计都在本地即时计算。

2. 整套系统的架构
================================================================

    life=time 的 HTML 文件          （程序本体，放在 iCloud）
          |
          |  快捷指令「life = time」打开
          v
    浏览器本地存储                  （日常数据存在这里）
          |
          |  App 内点「备份到 iCloud」→ 快捷指令「保存文件」
          v
    时光备份-日期.txt               （保险快照，存在 iCloud）

    整点自动化（17 条）——> 运行「life = time」——> 弹出记录界面

三个角色：
  · HTML 文件    = 程序
  · 浏览器存储   = 工作数据（每天在动的那份）
  · 备份 txt     = 保险（定期留下的快照）

全程没有服务器、没有第三方账号，数据不离开你的设备和 iCloud。

4. 日常使用流程
================================================================

【整点被提醒时】

  1. 自动化到点触发，弹出记录界面
     （手机锁屏时会先来一条通知，点一下进入）
  2. 顶部显示「刚过去」的那个时段，比如 14:00–15:00
  3. 选一个类别
  4. 打一句话说明具体做了什么（可留空）
  5. 可选：点一下「有意义／一般／虚度」
  6. 点「保存」

  保存后如果还有空着的时段，会自动跳到下一个，连着填几下就补完。

【错过了没填】

  不要有负担，这是设计里考虑过的。

  · 记录页顶部会提示「还有 N 个时段空着」，点「去补填」逐个补
  · 「今日时段」那条彩色条，点任意一格都能直接编辑
  · 「时间线」页可以翻到任意一天，逐小时补

  补填只回溯最近两天，而且不会早于你第一条记录。这是刻意的限制：
  一进来看到几十个空档只会让人直接放弃，两天是能补得回来的量。

【想看总结时】

  底部「总结」标签，日／周／月／年随时切换，不需要任何设置。
  积累两三天后图表才有意义，第一周结束时看周报会比较有意思。

【定期备份】

  设置 → 数据备份 → 「备份到 iCloud」，建议每月一次。
  超过 7 天没备份，记录页顶部会自动提醒你。

5. 三个快捷指令，各自负责什么
================================================================

── 快捷指令 A：打开程序（你命名为 life = time）────────────

  作用：把 iCloud 里的 HTML 文件渲染出来。

  动作 1  获取文件 → 选 iCloudDrive/时光观测台/时光观测台_5.html
  动作 2  显示网页视图

  这是你进入程序的唯一入口。


── 快捷指令 B：备份数据（你命名为 保存文件）───────────────

  作用：把剪贴板里的数据写成 iCloud 里的一个文件。

  动作 1  获取剪贴板
  动作 2  保存文件
            · 询问保存位置：关闭
            · 位置：iCloud云盘/时光观测台/data
            · 子路径：时光备份-[当前日期].txt
            · 如果文件存在则覆盖：关闭

  注意：中间不要加「文本」动作。快捷指令里每个动作默认接收上一个
  动作的输出，插一个「文本」会把剪贴板内容顶掉，最后存下来的只是
  那行文件名。

  这个名字要和 App 里「设置 → 数据备份 → 快捷指令名称」填的一致，
  App 靠名字调用它。


── 自动化 C：整点提醒（17 条）─────────────────────────────

  快捷指令 → 底部「自动化」→ 右上角 ＋

    触发：时间 → 9:00 → 重复「每天」
    动作：运行快捷指令 → life = time
    运行前询问：关闭   ← 不关等于没自动化

  从 9:00 建到次日 0:00，共 17 条，对应你设定的记录时段。

  建议先只建 9:00 那一条，到点验证能弹出来，再复制其余 16 条。


================================================================
6. 数据存在哪里（重要）
================================================================

数据存在浏览器的本地存储里，键名是 hourlog.v1，内容是一个 JSON：

    {
      "settings": {
        "startHour": 9,            记录时段起点
        "endHour": 1,              记录时段终点（跨午夜）
        "categories": [...],       你的类别列表
        "shortcut": "保存文件",     备份用的快捷指令名
        "ai": {...}                API 配置
      },
      "entries": {
        "2026-09-21-15": {         日期 + 起始小时
          "cat": "c1",             类别
          "note": "跑光谱拟合",     文字
          "meaning": "good"        主观评价
        },
        ...
      },
      "insights": {
        "week|2026-09-14": {       生成过的 AI 点评，按周期存档
          "text": "...",
          "at": 1758...
        },
        ...
      }
    }

容量：一条记录约 100 字节，一年约 5800 条 ≈ 600KB，
浏览器上限约 5MB，够用七八年。


★★★ 最需要注意的一点 ★★★

浏览器用「这个页面从哪来」作为存储的身份标识。你是通过本地文件
打开的，所以身份就是那个文件的路径和名字：

    iCloudDrive / 时光观测台 / 时光观测台_5.html

只要这个路径变了，程序就找不回旧数据了。包括：

    · 文件被改名（哪怕只差一个字符）
    · 文件被挪到别的文件夹
    · 下载新版本后文件名变成别的（比如 时光观测台_6.html）

旧数据并没有被删除，只是新页面读不到它。所以：

    不要重命名、不要移动那个 HTML 文件。
    更新版本时务必按第 8 节的步骤来。


其他会导致数据丢失的情况：

    · 长期（数周）完全不打开，系统可能回收存储
    · 手机重置、更换设备
    · 清除系统或 App 存储

以上任何一种，备份都是唯一的保障。


================================================================
7. 备份与恢复
================================================================

【备份】

  方式一（推荐）：
    设置 → 数据备份 → 点「备份到 iCloud」
    数据复制到剪贴板并自动跳转运行快捷指令 B，在
    iCloud云盘/时光观测台/data/ 下留下一个带日期的 txt。

  方式二（跳转失灵时）：
    点「仅复制」，然后手动运行快捷指令 B。效果完全一样。

  建议频率：每月一次。超过 7 天没备份，App 会自己提醒。
  文件名带日期，所以历次备份都留着，不会互相覆盖。

【恢复】

  1. 在「文件」App 里打开要恢复的那个 时光备份-*.txt
  2. 全选，复制
  3. 打开时光观测台 → 设置 → 数据备份
  4. 粘贴进下方的文本框
  5. 点「导入」

  导入会整体替换当前数据（包括设置和类别），所以如果当前还有
  没备份的新记录，先备份再导入。

  建议现在就完整走一遍恢复流程验证。备份只有在恢复被验证过之后，
  才算真的是备份。


================================================================
8. 更新版本的正确步骤（重要）
================================================================

因为数据和文件路径绑定，更新时必须保持文件名完全一致。

  1. 打开 App，点「备份到 iCloud」，确认备份文件已生成
  2. 把新版 HTML 放进 iCloud云盘/时光观测台/
  3. 把新文件改名成和旧文件一模一样：时光观测台_5.html
     （覆盖掉旧的）
  4. 用快捷指令 A 打开，检查记录还在不在
  5. 如果数据没了，按第 7 节把备份导入回来

第 1 步不要省。第 3 步的文件名必须逐字一致，包括下划线和数字。

如果嫌麻烦，也完全可以不更新——现有版本功能是完整的，
而且单个 HTML 文件没有会过期的依赖，放几年也照样能跑。

9. 功能详解
================================================================

【记录页】

  · 当前时段填写卡：类别 + 一句话 + 主观评价
  · 空档提示条：显示还有几个时段没填，可一键进入补填
  · 备份提醒条：超过 7 天没备份时出现
  · 今日时段条：16 个格子代表一天，点任意一格可编辑

【时间线】

  · 按天逐小时铺开，左右箭头翻天
  · 顶部显示当天的记录数、最多的类别、标记为有意义的小时数
  · 空格子可以原地补填

【总结】

  日／周／月／年四档，每档可前后翻页。包含：

  · 大数字：这段时间有多少小时被记录
  · 填写率：分母是「已经过去的时段」，不是全部时段，
            所以今天过到一半不会显示成 50%
  · 三个小指标：有意义占比、虚度占比、有记录的天数
  · 类别环形图：大扇区直接在图上标注名称和百分比，
                圆心是总小时数
  · 主观评价环形图：有意义／一般／虚度／未标记的构成
  · 类别排行列表：精确到小时和百分比
  · 每天（或每月）投入：堆叠柱状图看趋势
  · 时段镶嵌图（周／月视图）：横轴是一天里的 16 个小时，
    纵轴是日期，整周整月的生活铺成一张彩色格子图，
    作息规律和时间分布一眼可见

  所有图表和数字都是打开页面那一刻从原始记录现算的，不存任何汇总
  结果。所以你修改一条旧记录，所有受影响的统计下次打开自动就是对的。

  唯一会被保存下来的「总结」是 AI 生成的文字点评——因为它不是算出
  来的，重算要花钱，而且每次措辞都不同。见第 10 节。

【设置】

  · 记录时段：起止时间，可跨午夜（当前是 9:00 – 次日 1:00）
  · 类别：最多 7 个彩色类别，外加一个固定的「其他」。
          改名不影响已有记录；删除后旧记录会归入「其他」
  · 快捷指令名称：备份用的那条快捷指令的名字
  · AI 配置：见第 10 节
  · 数据备份：备份 / 仅复制 / 导入 / 清空
  · 两份内置操作指南

10. AI 文字洞察
================================================================

可选功能。会把你的统计数字和最近的文字记录发给大模型，生成一段
150 字以内的点评——指出一个你可能没注意到的模式，再给一条建议。

支持 Anthropic、OpenAI、DeepSeek 三家。key 只保存在本机。

设置方法：
  设置 → 文字洞察 → 选服务商 → 粘贴 key → 模型留空即可
  然后到总结页点「生成这段时间的点评」

成本：一次点评几百到一两千 token，量级是几分钱。
国内用户 DeepSeek 最省事（支付宝充值）。

【点评会自动存档】

  每生成一条点评，都会按「周期」存进数据里（比如 2026 年第 38 周
  的周报点评）。之后你再翻回那个周期，会直接看到当时生成的那条，
  不会重复消耗 API。

  · 想要新的：点「重新生成」，会覆盖旧的那条
  · 不想要了：点「删除」
  · 这些点评会随备份一起保存和恢复，设置页会显示已存档多少条

  所以这是一份会逐渐积累起来的、你自己的时间回顾档案。

注意：如果哪天你把这个 HTML 放到别人的域名下托管，浏览器的安全
策略可能拦截它直接调用服务商接口。用本地文件或自己的托管则不受
影响。

所有图表和统计都不依赖这个功能，不填 key 完全不影响使用。

11. 故障排查
================================================================

【打开后数据全没了】
  多半是 HTML 文件被改名或移动了。把文件名改回原来的
  时光观测台_5.html 再试。确实丢了就导入最近一次备份。

【点「备份到 iCloud」没反应】
  跳转被系统拦了。数据其实已经在剪贴板里，手动运行一次
  快捷指令 B 即可，效果一样。
  也检查一下设置里的「快捷指令名称」是否和实际名字一字不差。

【备份文件里只有一行文件名，没有数据】
  快捷指令 B 里多了一个「文本」动作，把剪贴板内容顶掉了。
  删掉它，只保留「获取剪贴板」和「保存文件」两个动作。

【整点没有弹出来】
  · 检查自动化的「运行前询问」是否关闭
  · 手机锁屏时不会直接弹，会先来通知，这是 iOS 的限制
  · 确认那一条自动化是启用状态

【填写率看起来偏低】
  分母是已经过去的时段。如果有整段时间没填（比如睡觉时段被
  算进了记录时段），去设置里把记录时段调窄。

【类别颜色不对劲】
  颜色按类别在列表中的顺序分配。删掉一个类别会让后面的颜色
  整体前移。改名不影响颜色。

【打开时一直卡在加载中】
  早期版本会去网上加载字体，网络不通时会一直等超时。当前版本
  已经完全去掉了外部依赖，不应再出现。如果仍然卡住，检查那个
  HTML 文件是不是还没从 iCloud 下载到本地——在「文件」App 里
  文件名旁边有云朵图标就表示还没下载，点一下先下载下来。


================================================================
12. 长期维护
================================================================

这个程序没有会腐坏的部分：单个 HTML 文件，零依赖、零构建、
零服务器、零外部请求，没有会过期的第三方包。放着几年不动也还能跑。

字体全部使用系统自带（中文宋体 + Georgia），不联网也能正常显示。

会随时间老化的只有一处：AI 的默认模型名是写死的
（claude-sonnet-4-5 / gpt-4o-mini / deepseek-chat），一两年后
可能下线。到时在设置的「模型」栏直接填新名字覆盖即可，不用改代码。

日常调整——改记录时段、增删类别、换 key——全部在设置里完成，
不需要碰代码。

数据格式是明文 JSON，任何文本编辑器都能打开，不存在被锁死的风险。


================================================================
最后
================================================================

这套系统能不能起作用，不取决于它有多少功能，而取决于你能不能
坚持填。所以有两件事是刻意设计的，值得说明：

第一，补填只回溯两天。错过几个小时不算失败，但也不要试图把
一周的空档补回来——那会让整件事变成负担。

第二，「虚度」这个标记不是用来自责的。它的价值在于月末回看时，
你能看见那些被自己当场判定为虚度的时间具体花在了什么上面。
知道比自责有用。
